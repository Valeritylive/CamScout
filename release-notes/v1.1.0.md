Большое обновление: Hikvision Device Manager стал заметно ближе к Windows-утилите SADP — с нативными SADP-командами, режимом командной строки и сбросом пароля.

> ⚠️ **Новые функции пока не проверены на реальных камерах и регистраторах.** Формат SADP-команд и запросов сброса пароля восстановлен по открытому реверс-инжинирингу, без официальной спецификации; неуверенные места помечены в коде как `GUESS:`. Пожалуйста, проверяйте сначала на тестовом устройстве и сообщайте о результатах в Issues. Неверный пароль несколько раз подряд может временно заблокировать устройство.

### Что нового

**Главное окно как в Windows SADP**
- Таблица устройств с теми же колонками, что и в Windows SADP (ID, тип, статус, IPv4, порт, версия ПО, шлюз, HTTP-порт, серийный номер, маска, MAC и др.), сортировкой и фильтром.
- Справа — панели «Активация устройства» и «Изменить сетевые параметры», как в оригинале.
- Индикатор сложности пароля (Опасный / Слабый / Средний / Надёжный) и правила пароля SADP: 8–16 символов, минимум два типа символов.

**Нативные SADP-команды по UDP 37020 (экспериментально)**
- Активация и смена сетевых параметров отправляются напрямую по SADP, без доступа к HTTP-порту устройства — работает и для устройств в чужой подсети, например с заводским адресом 192.0.0.64.
- При отсутствии ответа по SADP приложение автоматически пробует ISAPI. Если устройство по SADP отклонило пароль, ISAPI не пробуется, чтобы не заблокировать учётную запись.
- Консольный режим `sadp_protocol.py --dump` для отладки с выводом сырых пакетов.

**Режим командной строки (без графики)**
- Команды `interfaces`, `discover`, `export`, `activate`, `set-ip` — для скриптов, серверов и SSH-сессий. GTK не нужен.
- Пакетная активация (`--all-inactive`), раздача адресов подряд нескольким устройствам, `--dry-run`, вывод в JSON, выбор способа `--method auto|sadp|isapi`.
- Работает через AppImage и команду `hikvision-device-manager` из `.deb`; без аргументов запускается графический интерфейс.

**Сброс пароля (первая версия)**
- Двухшаговый сценарий, как в SADP: экспорт файла-запроса (GUID-файл через ISAPI или XML-запрос по серийному номеру) и импорт файла-ответа от техподдержки Hikvision с заданием нового пароля.
- Точные схемы запросов различаются между прошивками; для полностью заблокированных современных устройств может потребоваться код безопасности из официального SADP SDK.

**Исправления и прочее**
- Исправлено падение окна с полем пароля (`Gtk.PasswordEntry`).
- Исправлена сборка `.deb` на Ubuntu 22.04.
- Добавлены автоматические тесты (протокол SADP, CLI, колонки, сброс пароля); они запускаются при каждой сборке.

### Установка на Debian/Ubuntu amd64
Скачайте `hikvision-device-manager_1.1.0-1_amd64.deb` и выполните:

```bash
sudo apt install ./hikvision-device-manager_1.1.0-1_amd64.deb
```

### Установка на другие дистрибутивы Linux x86_64
Скачайте `HikvisionDeviceManager-x86_64.AppImage`, затем:

```bash
chmod +x HikvisionDeviceManager-x86_64.AppImage
./HikvisionDeviceManager-x86_64.AppImage
```

### Примечания
- Поиск и SADP-команды используют UDP-порт 37020; для ISAPI-настройки обычно нужен HTTP-порт 80, для видео — RTSP-порт камеры.
- HCNetSDK и HCSADPSDK в пакет не входят и устанавливаются отдельно из официальных пакетов Hikvision.

Исходный код и инструкции: [README](https://github.com/Valeritylive/hikvision-device-manager-linux#readme).
